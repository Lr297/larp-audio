# Audio ingestion and canonical WAV policy

## Scope

Компонент принимает путь к одному локальному media-файлу, читает metadata через `ffprobe`, выбирает один аудиопоток и создаёт канонический WAV для следующих стадий pipeline. Он не определяет и не удаляет паузы, не обрезает края, не выполняет STT и не создаёт пользовательские экспорты.

Исходный файл открывается только для чтения и никогда не является путём назначения. Для диагностики фиксируются размер и SHA-256 исходного файла.

## Executable resolution and process safety

`ffmpeg` и `ffprobe` разрешаются независимо в следующем порядке:

1. явный путь из конфигурации или CLI;
2. соответствующее имя в `bundled_tools_directory`;
3. системный `PATH` как fallback для разработки и технической CLI.

Явный путь является авторитетным: если он неверен, скрытый fallback не выполняется. В упакованном приложении bundled tools должны быть разрешены в абсолютные пути, а `PATH` не является runtime-гарантией. Ошибка перечисляет проверенные места и указывает, как задать путь. Автоматическое скачивание, сеть и добавление бинарников в репозиторий запрещены.

Все процессы получают список аргументов, запускаются с `shell=False`, ограничены timeout, захватывают stdout/stderr и проверяют exit code. Пути с пробелами и Unicode передаются одним аргументом. В логи не попадает полный JSON или содержимое пользовательских файлов.

Используемый JSON-режим и структура stream/format соответствуют официальной документации [`ffprobe`](https://ffmpeg.org/ffprobe.html).

## Audio-stream selection

Правило детерминировано:

1. из `streams` берутся только элементы с `codec_type == "audio"`;
2. выбирается первый аудиопоток с `disposition.default == 1`;
3. если default-потока нет, выбирается первый аудиопоток в порядке `ffprobe`;
4. при нескольких аудиопотоках в `AudioInfo.warnings` записывается индекс выбранного;
5. отсутствие аудиопотока является ошибкой.

Индекс выбранного потока затем явно передаётся FFmpeg через `-map 0:<stream_index>`, поэтому конвертер не повторяет неявный выбор.

## Duration and exact samples

Источники длительности имеют следующий приоритет:

1. `stream.duration_ts * stream.time_base`;
2. decimal `stream.duration`;
3. decimal `format.duration`.

Значения преобразуются в `Fraction`, без промежуточного `float` и округления. Container duration используется только как последний fallback. `total_samples` публикуется лишь тогда, когда `duration * sample_rate` является точным целым числом. Иначе поле остаётся `None` и добавляется предупреждение; дробная длительность сохраняется без потери точности.

Обязательны положительные `sample_rate`, `channels`, `codec_name` и неотрицательный `stream_index`. Отсутствующие необязательные поля не выдумываются. Malformed JSON, нечисловые значения и отсутствие обязательных metadata дают проверяемые ошибки.

## Canonical format

Для MVP формат фиксирован:

- container: WAV;
- codec: PCM signed 16-bit little-endian (`pcm_s16le`);
- sample format: `s16`;
- channels: mono;
- sample rate: 48 000 Hz.

Это даёт детерминированную дискретную временную шкалу, широко поддерживается FFmpeg и NLE и не вносит дальнейшее lossy-кодирование внутри pipeline. Конфигурация валидирует эти значения и не позволяет случайно изменить инварианты.

Даже полностью канонический вход пересобирается через FFmpeg. Один путь исполнения проще проверять, гарантирует новый корректный WAV header в рабочей директории и не подменяет источник копией с неизвестными дополнительными chunks. Скорость воспроизведения не меняется. Команда не содержит audio filters, loudness normalization, noise reduction, silence removal или trimming.

## Atomic publication and validation

FFmpeg сначала пишет уникальный `*.partial.wav` в каталоге назначения, то есть на той же файловой системе. Затем результат повторно проверяется через `ffprobe`. Публикация через `os.replace` происходит только если подтверждены:

- WAV container;
- `pcm_s16le` / `s16`;
- mono / 48 000 Hz;
- наличие выбранного аудиопотока;
- точное положительное число output samples.

Длительность сравнивается на шкале output samples, а не как `float` seconds. Для PCM-входа разрешено расхождение не более одного output sample. Для compressed-входа разрешено не более 2 400 samples (50 ms при 48 kHz), поскольку padding и container timestamps lossy-кодеков могут не совпадать с фактически декодированным сигналом. Превышение не публикуется.

При любой ошибке временный файл удаляется, а частичный итоговый файл не создаётся. Существующий итоговый файл заменяется только после полной проверки нового файла. Путь назначения, совпадающий с исходным, отклоняется до запуска FFmpeg.

## Error classes

- `ExecutableNotFoundError` / `ConfigurationError`: инструмент или configuration invariant;
- `ProcessTimeoutError`: превышен timeout;
- `ProcessExecutionError`: процесс не запустился или завершился с non-zero exit code;
- `AudioProbeError`: вход, JSON, stream selection или metadata;
- `AudioConversionError`: output format, sample count, duration или atomic publication.

Developer CLI возвращает `0` при успехе и `2` для ожидаемой project error. Она печатает metadata, но не является конечным UI продукта.
