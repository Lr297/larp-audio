# Граница MVP

## Статус Stage 11

Полный локальный workflow audio + exact script → cleaned WAV, edit map,
recognition, alignment, subtitles, processing report, manifest и ZIP теперь
подключён через один service, CLI и desktop screen. Packaging/installers,
automatic model management, waveform/player, editor XML и CapCut Draft остаются
за границей этапа.

## 1. Принцип отбора

MVP доказывает одну законченную пользовательскую ценность: из локального ElevenLabs-подобного аудио и оригинального скрипта получить безопасно очищенный WAV, точные субтитры из исходного текста и проверяемую карту монтажа без облачной обработки и без ручной установки runtime-компонентов.

В критический путь включается только то, без чего этот сценарий нельзя доставить и проверить. Совместимость с NLE, автоматические обновления и нестабильные приватные форматы не являются условием MVP.

## 2. MVP

### Пользовательский сценарий

- Отдельное desktop-приложение для Windows x64 и отдельных macOS-сборок для утверждённых архитектур.
- Минимальный GUI: выбор одного аудиофайла, загрузка/вставка оригинального скрипта, выбор каталога результата, запуск, прогресс, отмена, предупреждения и открытие результата.
- Один активный job. Очередь, многопользовательский режим и совместная работа не требуются.
- Входы хранятся локально и никогда не изменяются.

### Основной pipeline

- Проверка входов, доступного места и доступности упакованных инструментов/модели.
- Локальное декодирование и анализ аудио.
- Локальный STT с word-level timestamps; распознанный текст используется только для времени.
- Unicode-сопоставление ASR-наблюдений с точными диапазонами оригинального скрипта.
- Обнаружение длинных пауз по временным и аудиосигнальным признакам.
- Консервативное сокращение только безопасной середины длинной паузы с сохранением естественной паузы и speech guards.
- Правило `no cut + warning` для низкой уверенности, неоднозначного alignment и сомнительных границ.
- Сэмпл-точный `edit_map.json` и пересчёт всех последующих таймингов из него.
- Детерминированный subtitle chunking; отображаемые символы берутся только из оригинального скрипта.
- Staging, валидация и атомарная публикация результата.

### Обязательные артефакты

- `cleaned_audio.wav`;
- `subtitles.srt`;
- `subtitle_blocks.json`;
- `edit_map.json`;
- `processing_report.json`;
- `manifest.json`;
- ZIP-пакет, содержащий эти шесть файлов под фиксированными именами.

### Безопасный CapCut-режим

- `cleaned_audio.wav` и `subtitles.srt` пригодны для ручного импорта в CapCut Desktop.
- Можно предоставить отдельную краткую инструкцию или профиль ZIP, но он содержит только стандартные файлы.
- Приложение не ищет, не читает и не изменяет каталоги CapCut Draft.

### Качество, приватность и поставка

- Основной processing path полностью локален и проходит тест с заблокированным исходящим соединением.
- Пользователю не нужно устанавливать Python, FFmpeg, библиотеки или модель вручную.
- Версии runtime, sidecar, модели, policy и JSON schemas фиксируются в отчётах.
- Выпускаются отдельные platform-native пакеты; universal macOS binary не требуется.
- Release candidate проверяется на чистых Windows/macOS-системах.
- Публичная поставка требует обычной платформенной подписи/notarization, но не требует updater, MSI или сложной release-оркестрации.

## 3. После MVP

- Premiere FCP7 XML/xmeml для ограниченной, явно протестированной матрицы версий.
- Resolve FCPXML для ограниченной, явно протестированной матрицы версий.
- Editor-neutral `TimelineIR`, если он действительно нужен обоим экспортёрам.
- Дополнительные модели или quality packs после измерений на корпусе.
- Упрощённое управление версиями локальных моделей; полноценный model manager - только при подтверждённой необходимости.
- Опциональная история заданий; SQLite допустим только после отдельного решения и не является обязательным хранилищем.
- Автоматический updater приложения и отдельный канал обновления моделей.
- Дополнительные platform targets: macOS universal binary, Windows ARM64.
- Enterprise MSI и централизованное администрирование.
- Очередь нескольких локальных job, presets, расширенный просмотр отчётов и ручная коррекция alignment.
- Оптимизация или частичная миграция производительных/критичных компонентов в Rust по результатам профилирования.
- Расширение проверенной совместимости с отдельными версиями Premiere и Resolve; обещание «все версии» не даётся.

## 4. Экспериментальные функции

- Создание нового локального CapCut Draft для строго allowlisted версии и только в disposable/staging-каталоге.
- Rust core или Tauri shell как измеряемый post-MVP spike, а не заранее обязательная миграция.
- GPU/Metal/CUDA/Core ML acceleration profiles, если они не нужны базовым поддерживаемым сборкам.
- Альтернативные модели, diarization, forced-alignment engines и дополнительные языковые профили.
- Неавторитетная повторная транскрипция cleaned audio только для QA.
- Расширенные детекторы дыхания, музыки и выразительных пауз.

Экспериментальная функция скрыта за отдельным флагом, имеет собственные риски и критерии отключения и не блокирует выпуск основного продукта.

## 5. Явно исключённые функции

- Облачный backend или обязательная серверная инфраструктура.
- Django, Celery, Redis, PostgreSQL, S3/MinIO как архитектура продукта.
- Облачные AI API в основном pipeline.
- Учетные записи, роли, командная совместная работа и общий workspace.
- Телеметрия, analytics и автоматическая отправка crash reports.
- Автоматическая правка, переписывание, перефразирование, перевод или «улучшение» оригинального скрипта.
- Использование ASR-текста как отображаемого текста.
- B-roll, генерация видео, asset matching и функции reference SaaS-продукта.
- Изменение существующего CapCut Draft или автоматическое обнаружение пользовательских проектов.
- Прямой CapCut Draft в MVP.
- Автоматический updater в MVP.
- Enterprise MSI в MVP.
- Universal macOS binary в MVP.
- Полноценная система управления моделями в MVP.
- Обязательный SQLite в MVP.
- Автоматизация всех версий Premiere и Resolve.
- Premiere XML и Resolve FCPXML до стабилизации WAV/SRT/JSON pipeline.
- Облачная синхронизация проектов, публикация и remote processing.

## 6. Release-gate MVP

MVP считается ограниченным корректно, если его release-gate проверяет только:

1. безопасность pause removal и отсутствие word clipping;
2. достоверность alignment и сохранение исходного текста;
3. согласованность WAV, SRT и JSON с `edit_map.json`;
4. наличие и целостность семи обязательных результатов, включая ZIP;
5. локальную/offline обработку;
6. работу self-contained Windows/macOS-сборок;
7. ручной импорт `WAV + SRT` в CapCut как безопасный режим.

Отсутствие updater, XML-экспортёров, model manager, universal binary, MSI или CapCut Draft не является дефектом MVP.

## 7. Соотношение с документами этапа 1

Документы этапа 1 остаются аналитической базой и backlog, но не являются более новым продуктовым решением. При расхождении действуют `AGENTS.md`, `PRODUCT_SPEC.md`, этот scope и принятые ADR.

- Рекомендация Rust/Tauri в `PROPOSED_ARCHITECTURE.md` заменена для MVP решением `ADR-001`; её sample-based contracts, ports и safety rules сохраняются.
- Output tree с Premiere XML, Resolve FCPXML и CapCut Draft в `PROPOSED_ARCHITECTURE.md` описывает целевое развитие, а не обязательный MVP-набор.
- `IMPLEMENTATION_PLAN.md` остаётся инвентарём задач. Его runtime spike D-01 закрыт этим ADR, а milestone sequence должен быть перепланирован перед реализацией по текущей границе MVP.
- NLE/CapCut Draft risks и release blockers из `RISK_REGISTER.md` переходят в соответствующие post-MVP/experimental gates и не блокируют core MVP.
- NLE, updater, universal binary, enterprise MSI, full model manager и experimental draft sections из `TEST_STRATEGY.md` применяются только когда соответствующая функция входит в утверждённый release scope.
- Опциональный SQLite из `DEPENDENCY_MAP.md` остаётся необязательным и не появляется в MVP без отдельного ADR.
